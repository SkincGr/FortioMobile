# Changes — Βήμα 7: οθόνες που λείπουν

Η αναφορά του Fortio ζητούσε έξι οθόνες. Η κατάσταση στον τρέχοντα κώδικα:

| Οθόνη web | Πριν | Τώρα |
|---|---|---|
| Αρχείο με αξιολογήσεις (`/sender/archive`) | Υπήρχε (`shipments-archive.tsx`, δημιουργία και αλλαγή αξιολόγησης) | Χωρίς αλλαγή |
| Αναζήτηση για αποστολή (`/shipments/:id/route-search`) | Υπήρχε (`shipments/route-search/[id].tsx`) | Πρότυπα του είδους της αποστολής |
| Πρότυπα (`/sender/templates`) | Υπήρχε (`templates.tsx`, έτοιμα, δικά μου, αντιγραφή) | Διακόπτης είδους |
| Αναζήτηση δρομολογίων (`/routes`) | Δεν υπήρχε | Νέα οθόνη `routes-search.tsx` |
| Στοιχεία εταιρείας, Χρήστες | — | Μένουν μόνο στο web (απόφαση 27/10) |
| «Βοήθεια» στον Λογαριασμό | Γραμμή χωρίς ενέργεια | Ανοίγει email στο `support@fortio.gr` |

## Αρχεία
- `app/(tabs)/routes-search.tsx` (νέο) — αναζήτηση δρομολογίων μέσω `GET /api/routes`, όπως το `RoutesSearchClient` του web:
  - Υποχρεωτικά: αφετηρία και προορισμός από το Google (place id), ημερομηνία «από», αριθμός ημερών (3 / 7 / 14 / 30, έως 30 όπως ελέγχει το backend).
  - Προαιρετικά: ελάχιστος όγκος, αναζήτηση με ακτίνα, ταξινόμηση (ημερομηνία / τιμή / αξιολόγηση), σελίδες. Φίλτρο οχήματος `TRUCK,VAN` (η προεπιλογή του web).
  - «Επιλογή Αποστολής» συμπληρώνει αφετηρία, προορισμό και ±5 ημέρες γύρω από την επιθυμητή παράδοση. Με «Μόνο Νέα Δρομολόγια» κρύβονται όσα δείχνουν ήδη τα matches της αποστολής.
  - Κάρτα αποτελέσματος: εταιρεία, επαναλαμβανόμενο, απόσταση (ακτίνα), αξιολόγηση, διαδρομή με ημερομηνίες, «+N ακόμα ημερομηνίες», στάσεις, χωρητικότητα, χρέωση.
  - «Αίτημα Προσφοράς»: ζητά πρώτα αποστολή αν δεν έχει επιλεγεί. Μετά στέλνει αίτημα για αυτή την αποστολή με πρότυπο `REQUEST` του είδους της.
- `app/(tabs)/_layout.tsx` — η νέα οθόνη ως κρυφή καρτέλα.
- `app/(tabs)/index.tsx` — «Αναζήτηση Δρομολογίων» στο μενού του πίνακα.
- `app/(tabs)/profile.tsx` — «Αναζήτηση Δρομολογίων» στο μενού. Η «Βοήθεια & Υποστήριξη» ανοίγει `mailto:support@fortio.gr`.
- `app/(tabs)/templates.tsx` — διακόπτης είδους (Δρομολόγια / Μετακόμιση / Κάδοι / Ενοικιάσεις) όπως η σελίδα του web. Το `GET /api/templates` ζητά `kind`.
- `app/(tabs)/shipments/route-search/[id].tsx` — πρότυπα του είδους της αποστολής.
- `lib/i18n.tsx` — κλειδιά `dash.menu.route_search`, `tpl.kind_*`, `rs.*` (el/en/fr).

## Λογική
- Στο web το «Κάνε Αίτηση» ανοίγει τη σελίδα του δρομολογίου, όπου ο αποστολέας διαλέγει αποστολή και στέλνει το αίτημα. Το mobile δεν έχει σελίδα δρομολογίου. Γι' αυτό το αίτημα στέλνεται από την ίδια οθόνη, με το ίδιο `POST /api/messages` (`category: 'Offer Request'`) που χρησιμοποιούν τα matches.
- Το place id της αποστολής (`originPlaceId` / `destPlaceId` από το `/api/dashboard/sender`) είναι το Google place id, που δέχεται και το `/api/routes`.

## Επαλήθευση
- `npx tsc --noEmit`: 0 σφάλματα. Δεν δοκιμάστηκε σε συσκευή.

## API contract
Καμία αλλαγή στο Fortio. Το `GET /api/routes` είναι δημόσιο. Το `/api/templates` δέχεται ήδη `kind`.
