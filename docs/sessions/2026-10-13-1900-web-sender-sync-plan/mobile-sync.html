1. Κρίσιμα — δεν δουλεύουν σωστά σήμερα

Προέκυψαν επειδή το κοινό backend άλλαξε για το web. Το κινητό μιλάει στο ίδιο API, άρα επηρεάζεται ήδη.

Κρίσιμο

Τι άλλαξε στο web

  • Για μετακόμιση και κάδο δεν ταιριάζουν πια δρομολόγια. Ταιριάζουν μόνο κάρτες μεταφορέα.
  • Το API των αποτελεσμάτων επιστρέφει routes: [] και τη λίστα cards.
  • Ο μετρητής στο κουμπί μετρά τις κάρτες.

Τι έχει το mobile

  • Διαβάζει μόνο το routes. Για μετακόμιση δείχνει «Δεν βρέθηκαν δρομολόγια», ενώ το κουμπί στο dashboard δείχνει αριθμό.
  • Δεν υπάρχει τρόπος να σταλεί αίτημα σε κάρτα.

Τι πρέπει να γίνει

  • Εμφάνιση των καρτών (τίτλος, εταιρεία, κατάσταση αιτήματος).
  • «Αίτημα Προσφοράς» με πρότυπο, που στέλνει στο POST /api/routes/{κάρτα}/request.
  • «Δεν με ενδιαφέρει» και λίστα «Κρυμμένες» με «Επαναφορά» (/api/card-exclusions).
Αρχεία mobile: lib/api.ts · app/(tabs)/shipments/matches/[id].tsx · lib/i18n.tsx
Χρειάζεται πρώτα αλλαγή στο Fortio: το /api/routes/[id]/request δέχεται μόνο σύνδεση web. Με το token του κινητού απαντά 401. Πρέπει να αλλάξει σε getApiUser, όπως τα υπόλοιπα endpoints. Είναι αλλαγή ενός αρχείου.
Κρίσιμο

Τι άλλαξε στο web

  • Τα πρότυπα έχουν πλέον είδος: Μεταφορές, Μετακομίσεις, Κάδοι (transport_kind).
  • Προστέθηκαν 20 νέα δημόσια πρότυπα για μετακομίσεις και κάδους.
  • Το /api/templates φιλτράρει με &kind=. Χωρίς αυτό επιστρέφει όλα τα είδη.

Τι έχει το mobile

  • Δεν στέλνει kind. Σε μια κανονική μεταφορά εμφανίζονται και τα «Μετακόμιση : …» και «Κάδος : …».
  • Π.χ. η «Ακύρωση αιτήματος» δείχνει τρία πρότυπα αντί για ένα.

Τι πρέπει να γίνει

  • Το είδος βγαίνει από την κατηγορία της αποστολής: μετακόμιση → MOVES, κάδος → WASTE_BINS, αλλιώς TRANSPORTS.
  • Να περνά σε όλα τα παράθυρα προτύπων.
  • Ακύρωση πριν τη φόρτωση: για μετακόμιση και κάδο η κατηγορία είναι OFFER_CANCEL, όχι OFFER_CANCELL_BEFORELOAD.

2. Λειτουργίες που λείπουν από το κινητό

Υπάρχουν στο web και ο αποστολέας δεν μπορεί να τις κάνει από το κινητό.

Λείπει

Στο web

  • Κατηγορία WASTE_BINS με εικονίδιο 🗑️ και κλειδωμένο τίτλο «Προμήθεια Κάδου».
  • Δεν έχει αφετηρία. Ο προορισμός αντιγράφεται στην αφετηρία κατά την αποθήκευση.
  • Πεδία: προορισμός και διεύθυνση, ημερομηνία παράδοσης, εκτιμώμενη διάρκεια σε μέρες, άλλες πληροφορίες, χωρητικότητα κάδου (3, 4, 6, 8, 10 m³), παραλήπτης.
  • Δεν δείχνει διαστάσεις, βάρος, όγκο και ιδιότητες φορτίου.

Στο mobile

  • Η κατηγορία δεν υπάρχει στη λίστα.
  • Αποστολή κάδου που φτιάχτηκε στο web εμφανίζεται χωρίς εικονίδιο και ετικέτα.

Τι πρέπει να γίνει

  • Η κατηγορία στη νέα αποστολή, με τη δική της φόρμα.
  • Αποστολή του cardDetails: { binSize, durationDays }.
  • Εικονίδιο και ετικέτα στο dashboard, στη λίστα και στις λεπτομέρειες.
Αρχεία mobile: app/(tabs)/shipments/new.tsx · lib/api.ts · app/(tabs)/index.tsx · app/(tabs)/shipments/index.tsx · app/(tabs)/shipments/[id].tsx
Λείπει · μεγάλο

Στο web

  • Η μετακόμιση έχει κλειδωμένο τίτλο «Μετακόμιση Οικίας/Γραφείου».
  • Για αφετηρία και προορισμό: τύπος οικίας, όροφος, ασανσέρ, σκάλες, ανυψωτικό, στάθμευση.
  • Τετραγωνικά και δωμάτια, λίστες επίπλων και συσκευών, ειδικά αντικείμενα, υπηρεσίες, άλλες πληροφορίες.
  • Αποθηκεύονται στο cardDetails και τα βλέπει ο μεταφορέας.

Στο mobile

  • Η κατηγορία υπάρχει ως «Μετακόμιση Οικίας», αλλά με τη γενική φόρμα φορτίου.
  • Δεν συμπληρώνεται κανένα στοιχείο της κάρτας. Ο μεταφορέας βλέπει άδεια κάρτα.

Τι πρέπει να γίνει

  • Οι ενότητες της κάρτας στη φόρμα και στη σύνοψη.
  • Εμφάνιση των στοιχείων στις λεπτομέρειες αποστολής.
  • Είναι το μεγαλύτερο κομμάτι. Δες την ερώτηση 2 παρακάτω.
Αναφορά web: lib/moveCard.ts · components/shipment-form/MoveCardFields.tsx · components/MoveCardSummary.tsx
Λείπει

Στο web

  • Αφαιρέθηκε η «Περίοδος φόρτωσης / εκφόρτωσης». Μένει μόνο στους κάδους, ως «Άλλες Πληροφορίες».
  • Ο τίτλος της οθόνης αλλάζει: «Νέα Μετακόμιση», «Νέα Παραγγελία Κάδου», αλλιώς «Νέα Αποστολή».

Στο mobile

  • Το πεδίο υπάρχει ακόμα στο βήμα 2 και στη σύνοψη («Φόρτωση / εκφόρτωση»).
  • Ο τίτλος είναι πάντα ο ίδιος.

Τι πρέπει να γίνει

  • Αφαίρεση του πεδίου και της γραμμής σύνοψης, εκτός από κάδους.
  • Σε επεξεργασία, η παλιά τιμή να μη σβήνεται.
  • Τίτλος ανά κατηγορία.

4. Ήδη ίδια — δεν χρειάζεται δουλειά

  • ✓ Ημερομηνίες ως ημέρα/μήνας/έτος. Το κινητό τις έδειχνε ήδη έτσι.
  • ✓ Κουμπί «Επεξεργασία» στο dashboard.
  • ✓ Η ημερομηνία παράδοσης χωρίς «έως» μπροστά.
  • ✓ Η σειρά των προτύπων (order). Την εφαρμόζει το API.
  • — Μόνο για web: η μπάρα της επεξεργασίας (Προηγούμενη, Επόμενη, Ακύρωση), τα κουμπιά της κεφαλίδας, οι οθόνες του μεταφορέα και οι αναλύσεις φορτίων.

6. Αποφάσεις που χρειάζονται από σένα

1. Αλλαγή στο Fortio. Να γίνει η αλλαγή στο /api/routes/[id]/request ώστε να δέχεται το token του κινητού; Χωρίς αυτήν δεν δουλεύει το αίτημα σε κάρτα. Γίνεται σε συνεδρία του Fortio, όχι του κινητού.
2. Κάρτα μετακόμισης. Πλήρης φόρμα όπως στο web, ή απλή έκδοση στο κινητό (π.χ. όροφος, ασανσέρ, τετραγωνικά, άλλες πληροφορίες) και τα υπόλοιπα από το web;
3. Μενού ≡. Να φύγει η «Νέα Αποστολή» από το μενού του κινητού, όπως στο web; Στο κινητό υπάρχει ήδη το κουμπί + στο dashboard.
4. Έρευνα δρομολογίου. Για μετακόμιση και κάδο, να κρύβεται η «Έρευνα Δρομολογίου» στο κινητό; Στο web δεν άλλαξε ακόμα.
